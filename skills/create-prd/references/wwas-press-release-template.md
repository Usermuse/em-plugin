# Working-Backwards Press Release + FAQ

Write the announcement **as if the feature already shipped**, to force clarity on the customer benefit before any build. Every customer quote below must be a **real, attributed quote** pulled via a quote-angled `search` — never an invented testimonial. If no real quote fits a slot, leave it blank and note the gap rather than fabricating one.

---

## PRESS RELEASE

**[CITY] — [DATE] — [Company]** today announced **[feature/product]**, which lets **[customer segment]** **[core benefit in plain language]**.

**The problem.** [1–2 sentences on the customer pain, grounded in evidence.] [`1`](URL)

**The solution.** [How the feature solves it — the smallest thing that delivers the benefit.]

**Leader quote.** *"[Internal spokesperson framing the why]"* — [Name, title].

**How it works.** [2–3 sentences a non-expert understands.]

**Customer quote (REAL).** *"[verbatim quote from a real customer who described this exact pain or asked for this]"* — [Speaker, Account, date]. [`2`](URL)

**Call to action.** [How customers get started.]

---

## FAQ

**Customer-facing**
- *Who is this for?* [segment defined by the job/problem]
- *What does it replace or improve?*
- *What does it cost / require?*

**Internal / stakeholder**
- *Why now?* [what changed — cite evidence] [`3`](URL)
- *Why will customers switch?* [the evidenced pull]
- *What are we deliberately NOT doing in v1?*
- *Biggest assumptions / risks?* [flag for validation]
- *How will we know it worked?* [KRs tied to a stated pain]
